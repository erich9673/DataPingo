Files and uploads

Attachments are the slowest and most failure-prone part of a send, so most of the guardrails live here.

This app can attach files up to 150 MB — attach it directly in Jira on each issue that needs it.

One file is over the per-file ceiling. The limit is per file, not per comment — three 140 MB files are fine, one 160 MB file is not.

Do exactly what the message says: attach that one file to each issue directly in Jira, outside the app, then write the rest of the comment here as usual.

This send is over the 2 GB limit for one send — revise your comments, or send in smaller batches.

The app caps a single send at 2 GB written into Jira in total, counted across every issue in the batch. Issues are added together, not multiplied out: 700 MB on one, 1 GB on another and 300 MB on a third comes to exactly 2 GB and still sends. This is separate from the 150 MB per-file ceiling — a batch can breach the total while every individual file is well inside its own limit.

Split the batch. Send half the issues, then the rest — the total resets per send. Nothing was posted when the limit tripped, so there is nothing to clean up first. Remember that a file lands once per issue, so dropping issues from the selection cuts the total faster than shrinking the file does.

Jira did not finish attaching the files in time. Nothing was posted — try fewer issues, or a smaller file.

The upload ran past the time the platform allows. Larger files across more issues multiply: the same file going to 25 issues is 25 uploads.

Send to fewer issues in one pass, or shrink the file. Nothing was posted, so there is nothing to clean up before retrying.

The upload stopped making progress and was abandoned. Nothing was posted — try a smaller file, or fewer issues.

The transfer stalled rather than failed outright, usually a slow or interrupted connection.

Check your connection and retry. Keep the tab open while a large send runs — closing it stops the upload.

The site has exceeded its storage limit  /  Attachment quota exceeded for this instance

This is Jira’s own limit, not the app’s. A file lands once on every issue you send to, so a 100 MB video across 25 issues writes 2.5 GB.

Free space in Jira, or send to fewer issues. The confirmation before a large send shows the total it is about to write, so you can drop issues before anything is posted.

Permissions

The app acts as you. If Jira would refuse you, it refuses the app.

You don’t have permission to comment on the selected issue(s).

One or more selected issues sit in a project where your account cannot add comments.

Remove those issues from the selection, or ask a project admin for the Add Comments permission. The rest of the batch is unaffected.

No permission to add attachments

You can comment on the issue but not attach files to it — these are separate Jira permissions.

Post the comment without the attachment, or ask for the Create Attachments permission on that project.

Status changes

Transitions come from each issue’s own workflow, so what is available differs per issue.

That status change needs a field this app can’t set — do it in Jira

The transition has a screen attached that requires input — a resolution, an assignee, a custom field.

Move that issue in Jira, where the transition screen can be filled in. Its comment still posts normally from here.

I need to take a send back

There is no undo. It was removed in 4.6.0, because it could never honestly cover a service desk — a customer reply is emailed the moment it posts, so by the time you press undo the email has already gone. An undo that works on some products and not others is worse than none, because it teaches you to rely on it.

Delete the comments on the issues in Jira. The results screen lists every issue the send touched, with a link to each one, so you have the record of what to remove. Two things cannot be reversed: an email that has already reached a customer, and a status transition — move those back in Jira yourself. The confirmation before a send is what prevents this: it names the issue count, the storage total, and how many customers the send will reach.

Sending

What the footer counts and what stops a send from starting.

Add a comment or a status change to at least one issue.

Every selected issue still carries no badge, meaning nothing has been done to it yet, so there is nothing to send.

Open an issue and give it a comment, an attachment or a status change. Any one of the three makes it ready; the footer count tells you how many are.

Maximum 25 issues per bulk post

The selection is over the per-send ceiling.

Send in batches of 25. The tray along the bottom of the Issues step lets you drop issues with the × on each chip.

Some issues succeeded and some failed

Issues are posted in parallel and each is tracked on its own, so a partial failure is normal rather than a broken run.

Use Retry n failed on the results screen. It re-runs only the failures and leaves everything already delivered alone.

License

The license is checked at the moment you send. Everything else — browsing issues, writing, reviewing an earlier send — keeps working either way.

This site’s license is no longer active. Bulk Comments is free for teams of 10 or fewer — renew on the Atlassian Marketplace.

Atlassian reports this site’s subscription as expired or cancelled. It is not about your own Jira permissions — sending is unavailable for everyone on the site until it is renewed. On a site of 10 users or fewer this usually means an evaluation ended: the free tier is a subscription of its own, and a trial does not roll into it automatically.

A site admin opens the listing’s Pricing tab and uses Get it now, which starts the subscription — at no cost for 10 users or fewer. Apps → Manage apps in Jira will not help here: it lists what is installed and has no subscribe control. Nothing you have written is lost — drafts survive — and the app re-checks when you come back to the tab, so the same send goes through with nothing to retype.

The send button is greyed out, with “This site’s license is no longer active” beside it.

The same thing, said before you start rather than after. The button is disabled deliberately so you do not pick 25 issues and write 25 comments only to be refused at the end.

Use Renew on Marketplace → beside the message, then return to this tab. If it is still disabled, reload once. Browsing and writing are never blocked; only the send itself is.
