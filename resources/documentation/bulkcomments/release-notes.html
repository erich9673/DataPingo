Release Notes

v4.1.0 Latest August 3, 2026

Status changes move from a side effect to a first-class part of a send, and the size of a batch is now something you can see before it lands.

  • Change status as you comment — move each ticket while you write its comment, chosen from that ticket’s own workflow so you only ever see transitions Jira would accept. A status change counts on its own: a ticket with a new status and no comment is still included in the send.
  • Full ticket context beside the editor — open any ticket and its description, details and attachments sit next to the comment you are writing, along with every comment already on it.
  • Filter by status — narrow the ticket list by status as well as project, in your own workflow’s wording. Done work is hidden by default; one tick brings it back.
  • A storage estimate before every large send — the confirmation now does the arithmetic for you. A file lands once on every ticket, so 150 MB across 9 tickets reads as 1350 MB written into Jira, named before anything posts.
  • A 2 GB ceiling per send — totalled across every ticket in the batch. Anything larger stops before it starts and asks you to split it into smaller batches, rather than failing partway through and leaving some tickets done and some not.
  • Files over 150 MB are refused at attach time, the moment you add them, rather than after you have written the comment.
  • Clear all keeps your selection — it now clears the comments and status changes in place instead of emptying the ticket list and sending you back to the start.
  • The ••• actions menu opens the full app with that ticket already selected, instead of a cut-down compose box.

Undo does not revert a status change. It removes the comments a send posted and the files it uploaded, freeing that storage — but tickets stay where you moved them. Move those back in Jira.

v4.0.0 July 22, 2026

One page to write on, and a way back from a send that went out wrong.

  • One page to write — one comment for every selected ticket, and a different comment for any ticket that needs one, without switching screens.
  • Attachments up to 150 MB each, uploading while you write so they are ready the moment you send.
  • Undo on every screen — removes the comments a send posted and the files it uploaded, freeing that storage again.
  • Send progress now shows upload speed, elapsed time and a Cancel button.
  • Files copied with Copy a comment are recorded under your own name.
v3.7.0 July 17, 2026

The first version where every ticket could say something different.

  • A different note per ticket — write a separate comment for each selected issue.
  • Write or copy in context from an issue’s ••• actions menu and Activity tab.
  • Parallel posting for faster large batches, with a confirmation before sending to 10+ tickets or posting an @mention.
v3.4.0 – v3.6.0 July 16, 2026

Performance and reliability, plus the refreshed in-app icon.

  • Parallel comment posting and faster editor loading.
  • Per-ticket draft autosave, so a half-written batch survives a reload.
v3.3.0 July 9, 2026

Initial public release on the Atlassian Marketplace.

  • Write a comment once and post it to up to 25 Jira issues.
  • Copy an existing comment with its images, videos and file attachments.
